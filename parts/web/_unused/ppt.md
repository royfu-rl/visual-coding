## 1 The Execution Gate Is Already Open

PPT 方向在本文里是辅助方向。理由不是它简单，是**它最该被攻的那道闸已经被打穿了**。

- PPTAgent 的套模板编辑执行成功率 95.0%，GPT-4o 下 97.8%。
- 8B 的 AutoPresent 达到与 GPT-4o 相当的水平。
- Paper2Poster 的开源 Qwen2.5 版在多个指标上超过 GPT-4o 多 agent 方案，token 省 87%。

核心发现：任务一旦窄到有确定性 verifier，小模型就能打平前沿。这是本项目整张能力表上最一致的一条规律。

所以 PPT 不需要作为主力攻坚：**能不能跑**已经不是瓶颈，**剩下的差距在观感与版式**，而那一半靠加投入换不来可信提升。

PPT 方向的公开数据也是四类技术栈里最齐的：5 条管线，5 条数据全部可下载，产物格式收敛到 .pptx 与 Beamer 两种（python-pptx 占 3 条）。

## 2 Content Recall Already Beats Humans, Presentation Does Not

核心发现：同一个系统，答题式指标超过人类，整体观感只有人类的三分之一。

| 指标 | 系统 | 人类 | 口径 |
|---|---|---|---|
| PresentQuiz | 0.842 / 0.951 | 0.738 / 0.908 | 看视频答题正确率，内容召回型 |
| IP-Memory | 50.0% | 50.0%（持平） | 讲者身份记忆 |
| PresentArena | **17.0%** | 50% | 整体观感成对胜率 |

数据解读：答题式指标偏向内容召回，对整体呈现不敏感，所以 0.842 这个数不能当能力证明。同一篇工作里，去掉数字人与光标后 PresentArena 从 17.0% 掉到 15.2%——装饰只值 1.8 个百分点，救不了观感。

对照组更说明问题：端到端视频模型 Veo3 的 PresentQuiz 只有 0.367 / 0.585，IP-Memory 31.3%。**写代码出片对直接生成像素的优势是数量级的**，这一点在这个方向上已无争议。

剩下的两个结构性限制要一起说清：

- **基准规模太小。** 30 对（PresentAgent）、约 100 对（Paper2Poster）、101 篇（Paper2Video）。这个量级做不了可靠的模型对比。
- **设计质量只能靠 VLM 判。** SlidesBench 的 reference-free 设计质量、PPTEval 三维、PresentEval 三维全部是 VLM 判，而本项目对 VLM 判官的总体结论是只能作参考。

## 3 What A Deterministic Layout Verifier Would Check

公开工作里，溢出与对齐是由 VLM 修的——Paper2Poster 的 Painter-Commenter 环就是让 VLM 看图挑错。信号存在，但做法不是确定性的。

这件事必须自己做硬，而且有现成的反面教材。GLM-5 把幻灯片生成单列为一个训练任务（原文的小节标题是 Slide Generation），用静态、运行时 DOM 与包围盒、感知三级奖励。结果在 RL 中被刷穿：模型**硬截断溢出内容、操纵间距**。对策是修补渲染器消除可利用漏洞，再加视觉感知信号检测异常留白。

核心发现：只给感知奖励，版式会被刷；只给执行成功率，等于没判。

可以做成确定性判据的有四族，前两族已有现成实现路径。

| 判据族 | 怎么做 | 本地证据 |
|---|---|---|
| 执行与编译 | 幻灯片渲染成功、Beamer 编译通过，天然二值 | PPTAgent 95.0%、Paper2Video 的编译报错反馈修复 |
| 对象树回读 | 拦截 shape 构造，把每个版面对象映射回源码行，再读包围盒 | Visual-SDPO（[arXiv 2606.10334](https://arxiv.org/abs/2606.10334)）把这条和 matplotlib、DOM 两条并列写死 |
| 版面几何 | 溢出、两两重叠、出框，按阈值判 | 阈值可取相交面积比较小者面积 ≤ 0.05，且只限定在文本与交互元素之间 |
| 指令遵循硬约束 | 页数、标题文案、字数上限是否符合 query | 本地笔记零覆盖，这一族要自己从零建 |

回读比截图便宜两个数量级，这决定了判据选型：17 个页面的实测里，单页全流程中位 840 毫秒（渲染约 470 毫秒、截图约 110 毫秒），而**对象树回读只要 1 到 4 毫秒，是渲染耗时的千分之四**。回读能放进 RL 的每一步，截图不行。

抄这套几何判据有两个已知坑，踩了会把参考解判成错的：

- **文字包围盒必须过变换矩阵。** 不过矩阵，旋转文本全堆在原点，参考解会被误报 171 对文字重叠，而实际是 0 对。
- **溢出要分画布边界与绘图区边界两套。** 否则轴标题这类本就在绘图区外的元素会假阳性。

## 4 Why This Direction Rides On The Main Line

PPT 方向可靠的那一半判据——执行成功率、对象树回读、版面几何——和 html、webdev 主力线是**同一套机制**：读运行后的结构化状态，再做几何断言。主力线把这套机制做强，这个方向顺带就起来了。

不可靠的那一半是 VLM 观感打分，而本项目在相邻方向上实测过它与人评的相关系数是 −0.17。往这一半投入换不到可信提升。

一个顺手的线索：GPT-5.6 的发布页点名了幻灯片能力——能从参考 deck 反推出 design system，包括版式、字体、间距、配色，以及母版里的规则。这个任务形式正好可验证：参考 deck 的 design system 是已知的，模型反推出来的那份可以逐项比对。本地笔记里只有能力声明，判据还没人做。
