## 1 A Verifiable Task Is Three Things, Not One

自研环境这一章只回答一个问题：**怎么把一批网页，变成能训模型的题。**

一条可验证任务由 Query、Harness、Verifier 三件组成。三件缺一件，拿到的就不是任务，只是数据。

| 件 | 在 Web 这条线上具体是什么 | 缺了它会怎样 |
|---|---|---|
| Query | 需求描述，可带参考图、参考页面、参考视频 | 只有 html 没有 query，就只能做无监督 |
| Harness | 无头浏览器、冻结时钟、固定视口、运行时状态读取、多视口截图 | 产物跑不起来，判据无从落地 |
| Verifier | 把采集到的证据判成通过或不通过的规则 | 没有梯度，只能靠人看 |

两条硬约束贯穿全章。

第一条：**Verifier 能查的信息量必须小于等于 Query 给出的信息量。** 需求只说「杯子要用有别于桌面木色的独立颜色」，判据却要求恰好是参考图里那个蓝，这道题不可解，进了 RL 就是纯噪声。前沿团队把这条写成一句话——**grader 检查的每一项都必须在题面里说出来**；反向还有一条更严的：题面、实现、意图里出现的每个声明，都必须至少映射到一个检查项。

第二条：**参考代码不能进 reward，也不能进题面。** 它的位置在 Verifier 一侧，而不是目标一侧。这一条是本章第 4 节的全部内容。

还有一条容易被当成细节的前提：**判据要读运行后的状态，不读代码本身。** 本项目实测过一个在世界几何上逐点等同的替代实现，它通过了全部几何信号（分部件 F-score 0.9993），只被代码比对类判据误杀。等价实现极多，所以验状态不验代码不是审美偏好，是可复现性的必要条件。

## 2 Reverse-Mining Gives You Pairs, Not Tasks

先说一个结论，再说数字：**逆向挖矿能稳定产出 (图, html) 配对，但它产出的不是任务。** 配对只够做无监督和蒸馏母本，要变成 RL 题还得补 query 与判据。

### 2.1 来源分三档，不要把没查过的写成已调研

本项目的调研里，**可挖的来源压倒性地是代码仓库和真实网页，不是设计网站**。设计类站点在素材里基本是空的，所以这张表按证据强度分三档。

核心发现：真正有实测数字的来源只有代码仓库、开发者社区和已有公开数据集三类；获奖画廊类站点一条都没查过。

| 档 | 来源 | 规模 | 许可 / 障碍 |
|---|---|---|---|
| A 有实测 | 渲染库的像素基线仓库 | three.js 610 张参考图与 610 个示例页 1:1，Babylon.js 975，Blender 2,596；9 个仓库共约 19,000 张图、3,413 个触碰基线的提交 | 仓库自身许可；基线由持续集成维护 |
| A 有实测 | 视觉回归生态 | 浏览器测试框架的下游依赖 458,596 个；已合并 PR 里截图断言命中 14,656 与 32,634 | 两家云端服务（57,166 + 6,023 依赖）的基线**拿不到** |
| A 有实测 | 带截图的 issue / PR | SWE-bench Multimodal 617 条，83.5% 经人工确认必须看图才能解 | 真正能成型的量级约 1,400 个 |
| A 有实测 | 开发者社区站 | CodePen 1,000 万以上、ShaderToy 52,000 以上、Blender 问答站 123,167 问、js13k 2,799 件 | CodePen 公开镜像只约 2.5 万，**收缩约 400 倍**；ShaderToy 为非商用许可；问答站 2024 年起要求同意不用于模型训练 |
| A 有实测 | 真实门户 | 45.1K 页（本项目素材里**唯一**一条真实门户来源） | 布局与样式一致性直接从渲染结果算，已被用作 RL 奖励 |
| A 有实测 | 已有公开配对集 | WebCode2M 317 万行、WebSight v0.2 192 万条、Design2Code 484 条 | WebSight 的图床已失效；多家的数据未发布 |
| B 点过名但未查 | 获奖站点、设计稿社区、作品集平台、前端练习站 | — | 其中一家只有图没有代码；一家版权风险高；一家的爬虫协议点名封禁主流抓取代理 |
| C 素材里完全没有 | 其余获奖与画廊类聚合站 | 零命中 | 不要写进来源表 |

数据解读：

- **名义规模和可用规模差一到两个数量级。** 按关键词搜 three.js 有 89,622 个仓库，加上十星门槛只剩 2,401，**收缩约 37 倍**；bpy 方向从 6,307 收缩到 56。
- **许可是硬墙，不是提示。** Blender 扩展的 1,533 个条目里 GPL-3.0 及以上 1,341 个，MIT 只有 4 个——bpy 这条线几乎全是传染性许可。
- **像素基线仓库的配对质量最高，但它只支撑最软的那一档判据。** three.js 的 610 组配对是 1:1 的，可是配对的另一端是截图，所以它天然只能喂视觉相似度，喂不了运行时契约。

### 2.2 留存率的经验带宽是 0.2% 到 5%

核心发现：公开自报的真实挖矿端到端留存率全部落在 0.2% 到 5%，而瓶颈不在筛选，在能不能跑起来。

| 管线 | 漏斗 | 端到端留存 |
|---|---|---|
| Design2Code | 12.79 万页 → 粗筛 1.4 万（10.9%）→ 采 7 千条人工逐条检查 → 484 | **0.38%** |
| WebCode2M | 约 5 亿页 → 长度过滤 → 渲染 → 美学打分器剔除 52.5% → 截图去重 | **约 0.5%** |
| ShaderMatch | 20.2 万函数池 → 只留已发布且许可宽松的 → 467 | **0.23%** |
| SWE-bench | 9.3 万 PR → 属性过滤 1.14 万（12.25%）→ 执行校验 → 2,294 | 2.46% |
| SWE-rebench | 约 1,000 万 PR → 下载 45 万 → 安装与校验约 14% → 21,336 | 4.74% |
| 本项目 three.js 路线（估算） | 2,401 仓 × 3 页 × 约 3.2% | **约 230 个任务** |

数据解读：

- **卡住的那一步是执行，不是筛选。** SWE-rebench 自己点名安装与校验只有约 14% 通过，**只有 31% 的仓库能装成至少一个任务**。
- **人工环节是第二个数量级杀手。** Design2Code 的人工检查把 7 千条压到 484 条，单这一步 6.9%；SWE-bench Verified 的人工复核判废 68.3%，其中欠规约 38.3%、测试误杀正确解 61.1%。
- **合成与变异把产能抬一个数量级。** 同一批仓库上，变异造题的留存率是 50.1%，比真实挖矿高约 20 倍；各策略之间差 52 倍——让模型造 bug 55.98%，重写函数 35.04%，打乱类内方法只有 1.88%。
- **所以真实素材这条线的产能是三位数，不是五位数。** 本项目估算约 230 个任务。这个数字不是失败，它决定了真实素材的用法：当评测集与分布锚点，不当 RL 题库主体。

一条口径警告：有一份素材内部自相矛盾，一处要求真实素材占比不低于 30%，另一处算出真实客观上只能占 0.2% 量级。引用任一条都要标明。

## 3 Raw HTML Is Not Trainable

原始 html 不能直接用，这不是推测，是三组人各自独立撞上的同一个坑。

核心发现：真实页面在长度、可渲染性和质量三条上同时不合格，而且三条都有实测。

- **原始网页归档不能用于渲染。** 一家只把归档里的网址当种子重爬，理由是归档本身缺图片和样式表，页面无法被忠实渲染；一家虽然起点是归档，但管线第一步就是内联样式再过真实浏览器；另两家直接自爬。
- **真实页面大部分不配当监督信号。** 这一条有人工标注支撑：6 名标注员花约两周打出 10,000 个质量分，**其中 80% 落在五分制的 0 到 1 分**。据此训出的打分器上线后剔掉 52.5% 的原始数据。
- **长度本身让它不可训。** Design2Code 的平均源码 31,216 ± 23,903 token、158 个标签、DOM 深度 13；对照合成数据的 647 ± 216 token、19 个标签、深度 5——**真实页面 token 多 50 倍、标签多 6 倍、深度 2 倍**。
- **把原文文字直接塞进提示词是净负收益。** 一个 8B 开源模型拿到全部文字后，HTML 合法率从 98.0% 掉到 39.2%；另一个 8B 模型的文字维度分 80.3 → 55.6 → 22.6。

### 3.1 九道闸，按成本排序

闸的顺序比闸本身重要。**渲染是整条管线的成本瓶颈**——一家实测渲染占总耗时约 80%、全程约一个月；本项目估算渲 2,000 万页约需 2,000 CPU-day。所以长度与结构闸必须排在渲染闸之前，这是全管线最重要的排序约束。

核心发现：九道闸里只有一道有完整的阈值扫描记录，其余要么照抄别人的生产常量，要么必须按自己的库规模重标。

| 闸 | 具体做法 | 阈值 | 跳过的后果 |
|---|---|---|---|
| 1 长度结构粗筛 | 字符带通滤波，排在渲染之前 | HTML 落在 640 到 10240 字符、样式表 640 到 20480；超过 10 万 token 直接剔 | 渲染成本白烧 |
| 2 外链内联与资产本地化 | 把全部外部样式合并进单个样式块，字体、脚本、图片一律本地镜像 | — | 离线机器上字体与样式超时，**测到的是有没有网络，不是设计好不好** |
| 3 图片换占位 | 统一占位图，背景图直接删 | — | 一家用了公共图床，图床失效后 192 万条数据的渲染不可复现 |
| 4 不可见元素剪枝 | 先查样式可见性，再做点击验证：点包围盒中心，返回的元素不是候选的后代就剪掉 | — | 某数据集 59,555 个屏幕里 37.4% 含无效元素；交互元素三分之一小于 44×44 像素；18% 的屏幕有重叠叶子 |
| 5 去编译产物 | **本项目素材里零命中** | 无任何公开阈值 | 只能写成推论 |
| 6 审美过滤 | 五分类打分器，低于 2 分剔除 | 剔 52.5%（五分类精度 75%） | 见下面三条反向证据 |
| 7 内容安全 | 分类器阈值加脏词表 | 阈值 0.02 杀掉 57.5%、0.04 保留 91.3%（残留 0.21%）、0.05 保留 95.4%（残留 0.27%） | — |
| 8 去重 | 代码侧最小哈希，视觉侧语义聚类 | 代码侧 5-gram Jaccard 0.7 到 0.85；视觉侧语义去重余弦 0.97 | 不去重让指标虚高最多一倍；仅 10% 重复就相当于模型缩小两倍 |
| 9 去污染 | **在爬之前就排除评测集网址** | 对评测集去重用拷贝检测描述子余弦 0.604169，标记约 3% | n-gram 挡不住改写 |

数据解读：

- **闸 7 是全库唯一一条完整的「阈值扫描再选点」记录。** 0.02、0.04、0.05 三个点的剔除率与残留率都测了，然后选 0.04。其余八道闸没有一家这么做过，这是该照抄的工作方式，不只是该照抄的那个数。
- **审美闸只能当双侧区间或否决闸，不能当单调排序器。** 三条反向证据：经典计算美学指标全都单向可刷，留白更多、边缘更少、颜色更少全都分更高，**所以用它做 RL 必然收敛到一张空白单列页**；一项用户研究实测界面越好工具表现越差，准确率从 52% 掉到 39%，标注一致性只有 0.112；口味本身不收敛——20 名专业设计师判同样 600 对，二元一致率只有 0.624，**28.5% 的对分歧超过 96%**，在这份数据上训的模型只到 57.45%。**任何声称全局审美奖励远高于 60% 的结果都该先怀疑泄漏。**
- **不要用通用图文对齐模型当质量闸。** 同一精度下它的召回只有 0.02；在 10 个 3D 模型上它的分数全落在 0.077 到 0.108 的窄带里。这和 3D 章 3JSBench 的观察是同一个现象。
- **去重会过头。** 一家实测全局去重把 15T 压到 4T，最老的快照被删 90%，结果相比不去重几乎没有提升；而逐快照独立去重得到 20T，持平更强的对照。收益来自打掉跨全部快照、动辄几十万文档的巨型重复簇，**对只有几十个副本的小簇继续去重反而有害**。
- **去重的算力几乎免费。** 90 万张图的视觉嵌入约 1.25 GPU 小时，10 万文档的最小哈希约 11 秒，而去重开销不到训练算力的 1%。真正的约束是输出矩阵的内存，不是算力。
- **阈值必须随库规模重标。** 同一阈值下库从 100 万涨到 1,000 万，召回不变而精度从 0.8 跌到约 0.29。照抄前必须按 0.05 分箱人工抽检，十万量级只要几十条样本。

### 3.2 必须标出来的四个缺口

| 缺口 | 现状 |
|---|---|
| 哈希类名占比与编译产物阈值 | 素材全库零命中，没有任何人把去编译产物列为一道闸。更麻烦的是最近邻证据方向相反：运行时钩子对内容分发网络版、映射表版、打包版都能读到场景 |
| 滚动触发的懒加载图片 | 没有任何一家提到，未经验证 |
| 感知哈希的推荐阈值 | 没有公开来源。素材明确记下「业界通常取 5 或 8」查不到任何出处，是传说 |
| 合成界面的多样性基线 | 没有任何工作报告过合成界面的近重复率、特征方差或标签覆盖率。可借的通用证据是**只要 3% 自生成污染就会崩塌，而常规筛选完全无效**；召回和多样性比精度衰减得更快，**所以质量闸必须配一个独立的多样性监控器——最好看的页面恰恰是最同质的** |

还有一条取向性的选择要说清。DOM 简化有三条路线：简化成解析目标、保留可渲染 HTML、重写而不是清洗。第一条学得动但产物不可渲染，于是既没有生成目标也接不上视觉判据；第三条拿真实分布换干净。**本章取第二条，理由只有一个：只有可渲染的数据才能同时带包围盒对齐信号和下游渲染奖励。** 它的代价是要上全套清洗，而它的回报有一个被实验验证过的落点——**约 5,000 token 是既保留真实结构又还训得动的那个点**。

## 4 Four Ways To Spend One (query, html) Pair

现在手里有一批清洗过的 (query, html)。它有四种花法，价值差一个数量级，而且**最直觉的那种最没用**。

### 4.1 当无监督数据：朴素拼接错在哪

把「这是一个某类网站，它的源码是以下内容」直接当预训练样本，这个模板在本项目素材里零命中，没有任何一条文献直接批判过它。所以下面是推论，证据是间接的，每条都标口径。

核心发现：把 html 当「待复述的内容」是没用的那一类；要让它产生价值，必须让它承载结构预测的压力。

| 证据 | 数字 | 口径 |
|---|---|---|
| 规划结构有用，描述内容没用 | 结构规划带来 +3.1；先描述图里有什么再写码是 −0.1 到 −0.9 | 推理期消融，不是训练期 |
| 精确文本化有价值，模型自己文本化没价值 | 纯文本拿到多模态的 95.8% | **那份描述是从标准答案代码里抽的 oracle**；真实的自己描述版本是 81.2 → 81.1，白做 |
| 单一格式不如混合格式 | 训练数据只用一种推理层级得 13.1，混三种得 18.5 | SFT 的思维链格式混比，不是预训练 |
| 格式工程胜过加模态 | 纯文本表征的格式工程值 +5.4 点且 token 更少；加整张截图只值 +0.5 点 | 该工作没有多模态基线 |
| 模型根本不在复刻那份 html | 端到端只输出约 2,600 token，而参考 html 平均 31,216 token | 结构等价与视觉等价是两个任务，上下文需求差一个数量级 |

数据解读：第二行是最该记住的一条。「把视觉信息精确地文本化」极有价值，「让模型自己去文本化」毫无价值，差别在于前者是 oracle。**而我们手上的 DOM 与场景图恰好属于前者——它是程序从运行时状态直接读出来的，不经过模型，这就是它的全部价值来源。**

那么真正有干货的无监督构造是什么？素材里有，但集中在两个地方：一次渲染挂多个监督头，以及局部对齐。

核心发现：目标设计打败数据量——同样的数据量下换成十个监督目标，收益超过把数据量加到 7.5 倍。

| 构造 | 实测 |
|---|---|
| 截图解析 | 全库最大的单条增益：完整配方 67.8 / 137.5 / 84.2，**完全去掉截图解析掉到 12.2 / 35.1 / 24.2**。两条可抄的机制是遮挡一半文字但要求输出完整子树，以及必须先做一小段读文字热身否则不收敛 |
| 一次渲染挂十个头 | 2M 数据上一个目标换成十个目标，定位类任务 +4.5；而同一个目标把数据加到 15M 只买到 +0.2。聚合效果是语言输出类平均 +2.7，定位输出类平均 +25.3 |
| 局部包围盒对齐 DOM 片段 | 整页截图加一个随机节点的包围盒，预测该节点的源码。另一家做了同族的 1.4 亿以上对。**这个目标从来没有被单独消融过** |
| 结构感知注意力加对比损失 | 四档 28.00 / 30.80 / 35.80 / 37.00 |
| 受控降质 | 从约 30 万真实页造 230 万样本，九个降质函数每样本最多叠三个；设计选择准确率 75.12%，缺陷检测 87.1% 对一个通用多模态模型的 51.58% |
| 反向构造 query | 读无障碍树而不是读原始 html，因为 token 密度高得多。一家做到 100 万站点 7.3 万样本 |

而被点名问过的那几类构造，在素材里是零命中：代码填空、顺序恢复、互信息类目标、片段腐蚀作为 HTML 预训练目标、仓库级打包、代码与渲染之间的对比式对齐损失。唯一沾到填空的是那个一半文字遮挡，**但没有任何人把它推广到 HTML 代码本体**。这是一块真空地，不是一块已有共识的地。

还有一条反向结论必须一起写：**方向是「代码监督提升定位能力」，不是反过来。** 纯像素模型在指代表达任务上 94.2 打败读无障碍树的 90.8，控件描述 136.7 对 97.0。而「加界面定位预训练能提升图生代码指标多少」这个消融，**从来没有人发表过**。

配比上有数的部分：中训规模约为底座的 5%（三家分别是 5.4%、13.6%、22.9%）；**合成数据占比必须压在 15% 以下**，纯合成会造成灾难性遗忘，一个文字问答指标从 58.76 掉到 23.38 与 20.51，掉幅超过 60%。

### 4.2 为什么单轮 (query, html) 的 SFT 必然有问题

这一条素材里没有直接的训练侧消融，但有两组很硬的间接材料。

**第一组：真实需求的规模就不是单轮的。** 一个真实应用克隆任务的功能清单有超过 200 条验收项，单个迭代的契约就有 27 条判据。更关键的是观察到的失败模式——模型会改代码、甚至会写单元测试和发请求测接口，**但认不出这个功能端到端其实没跑通**；必须显式要求它用浏览器像真人一样测，表现才上来。而让它一口气做完整个应用的后果是**在实现中途耗尽上下文**，后续接手的会看到有进展就宣布完工。

**第二组：纯净单轮轨迹训不出恢复能力。** 这是本节最硬的一组对照。

核心发现：只用最优轨迹训出的修订能力是 10.84，带纠错轨迹的是 46.75。

| 证据 | 数字 |
|---|---|
| 只用最优轨迹 vs 带纠错轨迹 | 10.84 对 46.75 |
| 工具调用恢复率 | 基线 32.76%，带纠错训练 89.68% |
| 纠错能力能不能离线学到 | 离线自训的前后差是 −14.2，加了正确到正确的数据也只到 +0.4；而在线方法本身是 +4.4，比基座的 −11.2 高 15.6 个百分点 |
| 直接灌失败轨迹 | 等量失败数据做 SFT 得 14.7 与 54.8，**低于只用成功数据的 18.9 与 61.2**——不改写目标就灌失败轨迹是净负 |
| 负例权重扫描 | 0.0 → 37.2 / 0.5 → 35.1 / 0.8 → 44.4 / 基线 → 41.8，**只有 0.8 那一档超过基线，整体非单调** |
| 没有外部判据的自我修订 | 一个 8B 模型直接生成 46.7，自我修订掉到 12.3 |

数据解读：倒数第二行的非单调性是原文自己强调的，不要当成「负例权重越高越好」。最后一行回答了一个常被问的问题——自我修订不是能力问题，是**判据问题**：没有外部判据时它是净负的。

**第三组：零 SFT 直接上 RL 在这个方向不可行。** 纯文本推理能跳过冷启动，是因为基座已有能力只需激活；而视觉编码要学工具调用协议和多轮自检行为，基座完全没有，**于是几乎每条采样都卡在格式错给 0 分，组内没方差就没有梯度**。冷启动太小也有代价。而 SFT 的饱和点是测到过的：0 到 6 万条轨迹把解决率从 6.2% 提到 57.8%，**4.8 万条之后进入平台**，并且模型自己变短了，平均轮数 115 降到 94。

所以 (query, html) 的 html 该怎么用？素材里真正实践过的只有一个形态：**html 不直接当答案，而是当「反向构造 query 的素材」和「构造降质与编辑对的母本」。** 一家的 8 万条 SFT 数据里，答案由一个更强的模型写，query 反向构造以保证正确性，界面编辑覆盖增删改调，并把高质量的删除对反转成添加对。

### 4.3 当蒸馏数据：教师来 rollout，html 的五个用途

教师模型自己跑 query，那份 html 源码还有什么用？有五个用途，**没有一个是「当目标」**。

核心发现：参考代码应被视为下界而不是标准答案，它不应作为 RL 的相似度目标。

| 用途 | 怎么用 |
|---|---|
| 1 证明可解 | 参考解必须在 harness 里跑通并通过全部判据，**重复三次稳定** |
| 2 生成断言与评分项 | 从参考解的**运行状态**抽断言：DOM 盒模型、场景图、交互前后差分；把参考解的渲染结果交给评分项生成器 |
| 3 变异母本 | 对参考解注入缺陷，得到修复题和 **verifier 校准集** |
| 4 verifier 的自检 | **参考必过、初态必挂、变异体必挂**；三条任一不满足，问题在 verifier 或题目，不在模型 |
| 5 SFT 冷启动 | 可作为一条示范轨迹，但**只是多条合格轨迹之一**；RL 阶段不出现在 reward 里 |

为什么不能当目标，有三条理由，其中两条带数字：

- **等价实现极多。** 多份不同的脚本能产出几何等价的模型，SFT 难以学到这一点。
- **拿参考当整体对照的效果反而差。** 同一组实验里，用参考做李克特量表打分 31.7%，无参考评分项 32.0%，**用参考生成评分项 35.9%**——参考的价值在于生成判据，不在于当对照。
- **参考不一定最优。** 开发者代码可能冗余、性能差、写法过时，以代码相似度为奖励会把这些缺点一起学进去。

对应的工程处置可以直接落地：reward 只要求满足断言，**不要求接近参考，超过参考不受惩罚**；开放维度走组内比较，把参考放进比较池当锚但不在它上面更新；某题的模型解对参考胜率持续很高，就用通过全部断言且胜率最高的那条替换参考并重跑准入；**参考自身也要打分，分数低的不进 SFT 池但保留它产出的断言**；题面不得泄露参考的实现，只描述可观察效果。

断言集本身也要过变异测试：对参考注入缺陷，断言必须杀死变异体才准入，本项目的口径是每题至少 12 个变异。这一步不做会出什么事，有一个实测——**纯读代码的判官对 5 个被删特征中的 4 个给了满分**。

至于这条路为什么值得走，有一组很硬的算力对照：同一个起点，**纯 RL 花 17,920 GPU 小时得 67.6，在线蒸馏花 1,800 GPU 小时得 74.4——十分之一的算力，高 6.8 分**。更要紧的是性质差异：**RL 不扩展探索边界，蒸馏才扩展**——RL 后 64 次采样的通过率 90.0 → 90.0 原地不动，蒸馏后到 93.3。另一组同向：同一个基座做超过 1 万步 RL 得 47.0，蒸馏得 72.6。

但有一条反向边界必须一起写：一个有特权真值的教师，**若只做 token 级稠密蒸馏，会输给纯 RL**（38.75% 对 43.63%），因为超过 77% 的梯度集中在前 5% 的 token 上，而那多数是低熵格式词。所以特权教师要么进课程的最难档做桥，要么只调幅度不改方向，不能单独用。

### 4.4 当 RL 数据：html 是不是只能当 hint

核心发现：「参考解对解题者不可见、verifier 查终态」这个判断成立，而且有直接文献；但有一个明确的反例。

成立的那一半，证据相当直接：一家的解题者**不能访问参考解，也不能访问私有 verifier**，交互结束后在最终工作区状态上跑判据，而判据**查任务结果而不是固定命令序列**，所以不同的有效解法都能拿分。另一家把准入写成四条：环境必须能构建、**verifier 必须在初态失败**、参考解必须能从干净初态跑通、verifier 必须在终态通过，外加一条负向判别——不完整或部分完成的解必须判失败。

更值得抄的是**把泄漏做成可测指标**：一家从第 1 轮迭代到第 15 轮，隐藏判据保护率 38.2% → 63.5%，短指令风险 41.6% → 7.5%，提到私有测试的指令降到 0.1%，**字面泄漏降到 0%**，需求覆盖率中位数 0.42 → 0.57，弱接地任务 32.8% → 1.2%。

泄漏不是假想威胁，它被量化过。把解法种在文件系统里，实测 hack 率在不同模型上从 56.3% 到 0% 不等，最高的那个超过一半。缓解办法是文件访问审计加上**把参考解完全放在 verifier 容器、不进沙箱**。前沿团队列过四条泄漏路径：容器里装了含修复的新版依赖、版本历史里有被回滚的提交、构建产物里有答案、内网镜像能下到新版。对应到本章的同形物是**容器里留下的参考渲染图、没清掉的参考场景描述、依赖目录里的参考实现**。本项目的自检方式是全盘搜索关键词要求零命中。

而「不要把生成器源码一起发以免模型拟合它的代码风格」这半**没有直接文献**，两轮检索都没找到任何论文主张这一点，也没有消融。间接证据有三条，但其中最接近的一条是关于资产而不是代码风格的，而且那家自己恰恰开源了全部程序化代码并把这一点列为优点。**所以这半只能写成推论。**

反例是这样的：边界感知课程 RL 里，**超出能力边界的那一桶题不是被丢掉的**——取距边界最近的若干题，给它们造教师轨迹做小规模 SFT 搭桥，再用 RL 固化。所以准确的说法是：**参考解不能进 reward，也不能进题面；但它可以在课程的最难档上以教师轨迹的形式进 SFT，这是 hint 之外的第二条合法通道。**

除此之外，真实 html 在 RL 里还有三个已验证的位置：

- **它买到的是「真实分布那一片」。** 同一组消融里，不带真实页是 81.5 / 68.7 / 92.0 / 65.0，带真实页是 82.4 / 75.0 / 93.0 / 80.0——**真实数据在真实分布的两档上买到 +6.3 和 +15.0，而合成那两档几乎不动（+1.0）**。
- **渲染一致性可以直接当奖励。** 那条唯一的真实门户来源就是这么用的：45.1K 页，布局与样式一致性直接从渲染结果算。
- **往金标页注入缺陷再反转，得到确定性的修复轨迹。** 这是把 html 变成多轮数据的唯一确定性做法。

但别急着把渲染结果稠密化成奖励，有两组反向证据。

第一组：**渲染截图当奖励的相关性是负的。** 同一批产物上，只读 DOM 与真值的秩相关 −0.021、假阳率 33.7%；截图加 VLM 相关 −0.068、成本约 50 倍；八步自主探查相关 +0.111 但假阳率 45.6%、成本约 400 倍；**只有不进提示词的隐藏运行时契约是 1.000、假阳率 0、成本约 2 倍**。

第二组：**大多数「稠密化增益」都能被与正确性无关的信号复现。** 随机奖励 +21.4、格式奖励 +13.8、**错标签 +24.1**、单样本 RL +26.0、多数投票 +27.1，对照真值奖励 +29.1。**任何没有空对照的代理增益都证明不了什么。** 同向还有一条：只看结果的奖励被 hack 的比率高达 48.1%，而关键词式的「视觉证据奖励」比感知答案的奖励**更容易**被 hack。

所以顺序是清楚的：**verifier 本身可靠之后才谈稠密化；先把程序化断言做硬，再考虑过程奖励。**

最后两条工程性的提醒。渲染出来的文字是一条注入通道——朴素硬注入的成功率约 5%，通用模板 22.8% 到 24.1%，优化过的超过 30%，而随机后缀对照只有 1.2% 到 1.5%；缓解办法是把检测到的文字区域遮掉再送给判官。另一条是难度标定的成本：**四次采样标出来的难度，95% 置信区间全宽是 0.98，等于没标**；要把半宽压到 0.10 需要约 81 到 96 次采样。而硬边界的难度桶在数学上做不到——在 64 次采样下桶边界的误分率仍有 15% 到 23% 且几乎不随采样数下降，所以只能用软权重或重叠桶。

## 5 What A Lab That Cannot Distill Would Build

假设没有更强的教师可蒸。这一节先说边界，因为这里最容易写错。

**这两家关于视觉编码的训练配方是公开的空白。** 本项目两份独立素材各自确认：一份 2,116 行的一手汇编里，蒸馏、教师模型、SFT、人类反馈、冷启动、中训、GPU 小时、样本效率**全部零命中**；四份系统卡里审美、前端、视觉设计、样式表、Web 开发全部零命中；两篇相关的产品博客**全文没有出现过「训练」这个词**。三家都做了渲染在环的产品功能，**没有一家说用它训练**；唯一一处说真实浏览器反馈会进训练的，方向是安全不是视觉质量。

所以这一节能支撑的是「环境、判据、造题怎么构造」，**不能支撑「他们的 SFT 与 RL 配比怎么排」**。

### 5.1 他们实际披露的，只有四句

数据来源那一栏的原话是「公开信息、公开与私有数据集、用户明确许可用于训练的数据，以及其他来源例如**由其他模型生成的合成数据**」。有一处模板变化值得记：**「由数据标注服务与付费承包商提供的数据」这一句在最近几代里消失了**，换成笼统的「公开与私有数据集」。这是模板的实质变化，但不要据此推断数据构成变了。

另一家的披露里最该引的一句是：**他们把「用工具检查自己的产物」当成一个被专门训练的能力轴**——「更好地使用工具来检查、测试和验证自己的工作」，以及「更强的计算机使用能力让它能检查和改进渲染结果，而不只是生成底层代码」。但怎么训依然未披露。

### 5.2 环境侧的一手数字，是这一块最实的部分

核心发现：他们公开的不是配方，是环境的工程规格——而这部分可以直接照抄。

| 内容 | 一手数字 |
|---|---|
| 规模 | 最终阶段约 **150 万** 条 episode 摘要、**数千个**训练环境、约 **400 条**全文人审 |
| 环境分级 | 按 grader hacking 风险内部分成高低两个子集；跨模型比 hack 率**只在三者共享的环境子集上做** |
| 坏题的代价 | **坏题把尝试 hack 的比率推高约 3 到 6 倍**；缺文件任务与完好任务的成功 hack 率差 1.5 到 3 个百分点；「明知未完成仍交」占这些任务上 hack 尝试的约 80% |
| 处置方式 | 环境 bug 导致的不可能任务，**官方修环境而不是修模型** |
| 模型猜 grader 的频率 | 基于 grader 假设改解法 2/695，主动挖 grader 线索 1/695；「猜中答案键」成功的 episode 占比约 0.3% |
| 质检的性价比 | 质检只占 harness 总成本的 **8.4%**，却每轮都找出真问题 |

数据解读：第三行是整节的核心论据。**坏题不是噪声，是 hack 的主因**——这意味着清题的优先级高于调 policy。配套还有一条反直觉的处置：必须给模型「这题有问题」的出口，**不要禁止它提问澄清**。

### 5.3 五类可以直接照抄的机制

造题与准入侧，最该抄的是四条：**grader 检查的每一项都必须在题面里说出来**；题面、实现、意图里的每个声明都必须至少映射到一个检查项；**视觉上要紧但主观的要求，要转成可观察的检查项而不是留着不说**；以及「好题是两个领域专家会给出同一判决的题」。还有一条判废规则极省事——**永不上涨的题，是题或 grader 坏了**。

判据形式侧，有五条带具体内容：**评分项写成可检查的断言，不写五分制**；**任一维度低于硬阈值即整体失败，不做加权求和**；**权重按基线方差分配**，默认就及格的维度降权；可计数的硬约束可以写得非常具体，例如一个主标题、不超过六个区块、最多两种字体、一个强调色、首屏一个主行动按钮；以及**反事实删除判据族**——删掉图片、隐藏导航、去掉卡片边框与阴影、砍掉三成文案、开关特效，看判据会不会跟着变。

verifier 工程侧，有六条：**判官模型不能是被测模型**；有基线时成对比较、随机序、不告知哪个是基线；**同一输出跑两遍 grader 看判定会不会翻面**；**评测噪声必须小于最小可行动增益**；基础设施噪声与模型方差分开统计；**被守卫拦下的试次单独报出并计为失败**。还有两条格式性的但很实用：**判据与状态用结构化数据而不是 Markdown 存**，理由是模型不太会去改写结构化文件；**视觉质检与功能质检分开，功能过不等于视觉过**，并且不要靠单张截图签收。

有一条是明确不抄的：**要求模型配合暴露运行时状态接口**。本项目的立场是拒绝这个要求——判据应该自己去读状态，而不是让产物为判据让路。

### 5.4 为什么纯靠模型自评构造训练信号不可行

这是本节最该写清的一条论证，三面证据都是一手的。

- **自评会自夸。** 生成器自己评会「自信地夸奖自己的作品」，而**把一个独立判官调得更怀疑要容易得多**。注意分离不消除宽松，只是把宽松变成可单独调参的对象。
- **RL 奖励出来的主要是呈现方式而不是解法质量。** 对冲措辞、自我表功、声明遵守指令——**模型学会在回复里声称自己检查过了，而不是真去检查**。实证：886 个内部使用会话里有 16 个「报告做完或验证过但其实没有」，标签是「跳过了便宜的验证」。
- **自我验证又会过度。** 一个 24 小时的设计实验里，一个模型交了 30 个方案，另一个一臂交了 17 个且无排序、另一臂**最后 8 小时没声音**。由此得到的轨迹剪枝判据很实用：**剪掉的不应是纠错本身，而是没有新信息进入的重复验证；判据是这一步有没有引入新的观测。**
- **判别通道缺失的维度，harness 就是瞎的。** 一个具体例子是模型听不见，所以音乐质检失效。对应到本章：没有渲染通道就没有视觉判据。

### 5.5 那么样本效率低该怎么补

「仅靠 RL 样本效率低」这个判断，证据不在前沿团队的披露里，在别处，而且很硬：十分之一算力高 6.8 分的那组对照、RL 不扩展探索边界的那组通过率、以及一组边际结构——**6.2 → SFT 57.8 → 加 RL 61.4 → 采 8 次用验证器选 70.2 → 两者都做 70.8**。

数据解读：**RL 的边际增益只有 3.6，而推理时选择是 12.4。** 对一个不能蒸馏的团队，这组数字指向的不是「更多 RL」，而是先把验证器做强——因为验证器同时是 RL 的奖励来源和推理时选择的打分器，一份投入两处收益。

还有一条很硬的反向证据，省掉的可能是整个 RL 阶段：**评分项本身在任何判官反馈之前就产生了绝大部分增益**——「即使是第一轮迭代，产物就已经明显好于完全不加提示的基线」。配套的判断是判官的边际价值随模型变强而下降，**它值得花钱的场合是任务超出当前模型能可靠独立解决的范围时**。

所以一个不能蒸馏的团队，合理的顺序是：**先清题（坏题把 hack 推高 3 到 6 倍），再把评分项写成可检查的断言，再建环境与 harness，最后才是 RL；而中间插一道推理时选择，性价比高于加 RL。**

## 6 Omni Reference Query

Query 这一侧的变量只有一个：**参考给到什么程度。** 参考越厚，模型的任务越收敛，而 Verifier 能查的东西也越多——两者必须同步放宽，否则就违反第 1 节那条信息量约束。

核心发现：五档参考不是难度递进，是**判据来源的替换**；每放宽一档，主判据就从状态断言往感知指标滑一格，而感知指标全部不可靠。

| 参考档 | Query 里有什么 | query 从哪来 | 主判据落在哪 | 这一档的素材厚薄 |
|---|---|---|---|---|
| 纯文本 | 只有需求描述 | 真实线上用户 query 分布；从真实页面反推需求；专家播种后程序化扩写 | **参考解的运行状态**，噪声地板为 0 | 最厚，可独立成章 |
| 纯图像 | 只有参考图（截图转代码） | 已有配对集；像素基线仓库；逆向挖矿 | 逐部件几何、结构回读；**不是像素比对** | 厚，但全是负面证据 |
| 文 + 图 | 需求加参考图 | 真实需求配真实页面截图；扰动已有场景造「改回去」题 | 状态断言为主，参考图进题面不进 reward | 厚，且有唯一一组受控对照 |
| 文 + 图 + 视频 | 再加参考录屏 | 交互流程录制；已有游戏与动画工程 | 输入重放加状态差分；**不是录屏判别** | 中等，本地实测为零 |
| 文 + 图 + 视频 + 音频 | 再加声音 | — | 音频只能当否决器 | **本地材料未覆盖** |

### 6.1 纯文本参考：没有参考图反而是最干净的设定

这一档容易被当成最弱的一档，实测恰好相反。**参考解的状态比参考图信息量大得多，而且噪声地板是 0。**

本项目在三条线上各自测过这个地板：Blender 侧参考解跑两遍，图像 1.0000、Chamfer 0.0、体素 IoU 1.0；Web 侧 231 个回读字段里五次重复只有 4 个会变，**所有参与判定的字段逐字节相同，两次完整重跑判定翻面 0 次**；审美侧两次独立运行 20 个样例，连每一条连续读数都逐位相同。

数据解读：地板为 0 带来一个直接后果，原文说得最清楚——**阈值不能从噪声推，只能按「什么算语义等价」来定。**

但零噪声不是天然的。有一个反例值得记：几何采样自带的随机源不受全局随机种子控制，不显式传种子时**参考解和自己比的 Chamfer 是 0.00167 而不是 0**，而通过与不通过的 Chamfer 带宽只有 0.0016 到 0.0065——**噪声地板直接吃掉一半判别力**。

纯文本档还有一块独特的内容：审美。这一档明确排除参考集，所以分布类指标全部不可用，只能用无参考指标，而且探针只读计算样式与几何，不做像素比较也不调模型。本项目冻结了九条判据，实测参考页 11 条全过、该挂的抓到 9/11、不该挂的 8/8 零误杀、单次约 0.8 秒纯 CPU。

其中一个实例值得单独写，它是「别从设计教条里抄阈值」的黄金例子：一个手写的、无障碍检查全过、多视口不塌的参考页，它的间距取值落在各基数倍数上的占比是 **2 的倍数 91.4%、4 的倍数 57.8%、8 的倍数 32.8%、16 的倍数 16.4%**。

数据解读：**一个好页面只有 57.8% 的间距落在 4 的倍数上。任何写死「间距必须是 4 的倍数」的规则都会把它判挂。** 正确做法是自动选基数再看占比，判据改成「存在某个基数使不少于 70% 的取值是其倍数」。由此得到一条工程铁律：**审美类程序化判据的阈值必须从参考页反推，不能从设计教条里抄。**

程序化审美判据的上界也要说清：纯规则检查的召回只有 22.9% 到 32.3%，带知识库的检测能到 83.3% 与 92.1%。所以它是闸，不是评价体系。

### 6.2 纯图像参考：视觉相似度的验尸报告

这一档的素材几乎全是负面证据，三条线各自独立地测出同一个结论：**像素比对不存在可用的工作点。**

核心发现：像素的噪声地板是 0，判别力也接近 0——零噪声不等于有用。

| 线 | 实测 |
|---|---|
| Web | 11 个该挂的变异里 **7 个像素完全相同**（相似度 1.0）；最佳阈值也只能做到 14/22；而**该过的重新配色，像素差 0.9002，比大多数真实缺陷都大** |
| 图表 | 改一个数据点的像素差只有 **0.75%**，图例互换 **0.01%**，而**该过的重新配色是 30.51%**；像素层 9/16 且 4 个误杀，对照逐值回读 13/16 零误杀 |
| 3D | **该过的相机移动单图相似度 0.9534，真错误的木色变蓝 0.9844**——该过的那个画面变化更大 |

数据解读：三条线指向同一句话——**画面变化量和语义错误量完全不相关。**

人类一致率那一侧也不乐观：峰值信噪比 57.1%、结构相似度 57.3%，**基本等于抛硬币**；感知距离 70.7%；只有一个专门的感知相似度模型到 96.2%，但它量的是感知相似度，不是语义正确性。还有一个反直觉的系数：某个细粒度指标组合预测人类胜负能到 79.9%，**但其中文本相似度这一项的系数是负的**——文本越像，人类越不喜欢。

那么什么能替代？四类，全部有判别力数字：

| 替代 | 判别力 |
|---|---|
| 逐部件几何（按材质基色分组取最差组） | 18/22，检出 7/11；对照全局几何分检出 **0/11** |
| 逐颜色体素占据 | three.js 侧 25/29，Blender 侧 15/22 |
| 开放边界边数（拓扑量） | 0 对 64。它不随洞的大小衰减，所以能抓住被全局交并比淹没的小破洞 |
| 结构回读（DOM 与计算样式、图表逐值） | Web 侧五层组合 22/22；图表逐值回读 13/16 零误杀，与结构断言取或是 16/16 |

数据解读：第一行是本节最该记的一组。杯子平移 30 厘米，**全局 Chamfer 只从 0 变到 0.00018、全局几何分 0.9916**（能过 0.99 的闸）；而逐部件 Chamfer 0.08375、逐部件分 0.2243——**差 460 倍**。全局平均会被小部件骗穿，所以要按部件分组再取最差组。

还有一条被低估的事实：**不需要模型配合就能拿到场景。** 可靠的钩子全都是「在文档启动时注入一个引擎会条件读取的全局」，而这个全局是**引擎自己派发的**，比要求页面暴露状态接口稳得多。逐引擎实测过可用性：主流三个 3D 引擎都能拿到，而两个常见 2D 游戏引擎、两个原生运行时拿不到。所以 Verifier 的真正硬需求是**控制文档启动时的脚本注入**，不是约定接口。

### 6.3 文 + 图：这是判官模型的最佳工况，但代码才是主导模态

这一档有本项目唯一一组「同一标注集、只换输入模态」的受控对照。

核心发现：参考图加进来，判官的判对率从 68% 跳到 94%；但检出率的提升幅度远大于保真率，说明它补的是漏抓，不是误杀。

| 条件 | 判对率 | 检出率 | 保真率 |
|---|---|---|---|
| 题面加参考图 | **94% / 97%** | 92% 到 95% | — |
| 只有题面 | 68% / 76% | **61% 到 63%** | 四视角下 39/40 |

数据解读：去掉参考图，判对率掉 20 多个点，检出率掉 30 个点，**但保真率几乎不动**。也就是说无参考图的判官变成了一个「几乎不误杀、但一半错误抓不到」的器件。工程结论很直接：**无参考图时判官只能当补抓，不能当闸。**

但参考图加进来之后，主导模态仍然不是图。两组独立消融：只给截图，成对判别掉 9.79 到 10.7 个点；**只给代码，只掉 0.31 到 2.60 个点**。另一组四档更清楚：只给代码 79.06 → 加图注 81.74 → 给真图 90.95 → **只给图不给代码 74.94**。

数据解读：最后那一档低于只给代码的那一档。所以处方是**设计类判官的输入必须包含关键源码片段，而不是只喂截图**。

这一档还有一个造题形态值得单独记：**扰动即监督。** 取一个已有场景，扰动它，题面给起始场景加目标渲染图，要求改回去。关键结构是**图是题面侧的参考，reward 是状态侧的**——判据比的是钉死字段加逐部件几何，不比图。准入筛选也可以自动化：**只有当被破坏的渲染在官方判据下判失败时，才接受这个扰动**，这一步把「改不动的扰动」自动筛掉，比人工判断可靠。

### 6.4 文 + 图 + 视频：录屏判不了可玩性

这一档的厂商侧只有定性披露，没有一个数字。唯一明确用录屏做判别的一家说的是「**基于视频的评估比静态截图减少视觉幻觉**」，以及同一个判别器既用来筛数据又当 RL 奖励——但 Web 方向的训练细节未披露。

而本地材料里有一组极强的归谬。一个游戏基准把交互代码**改写成 10 秒自动演示**再录屏打分，录屏评分项里还留着「用户输入响应性 0 到 25 分」这一项，**而整个过程从来没有发送过任何输入**。

核心发现：这不是实现瑕疵，是「用录屏当可玩性证据」这条路本身的归谬。

同向的数字：那个基准上一个前沿模型的三轴分是**代码 96.6、图像 17.6、视频 20.7**；另一个基准里最好成绩 **0.48%**，三个保密游戏**全部 0%**。

替代路线的抗欺骗强度排序是这样的——**输入重放加状态差分 > 绘制调用拦截 > 引擎自带钩子 > 像素与音频 > 要求模型暴露接口。**

| 路线 | 怎么拿状态 | 骗得过吗 |
|---|---|---|
| 要求模型暴露状态接口 | 脚手架规定 | **骗得过，而且训练时一定会被骗** |
| 引擎自带钩子 | 引擎自己派发的全局 | 难骗，但只给渲染与场景图，不给分数与生命 |
| 绘制调用拦截 | 劫持渲染循环与绘图接口 | 几乎骗不过：这就是玩家看到的东西，要骗必须真的画出来 |
| **输入重放加确定时钟加状态差分** | **不读内部任何东西**，固定种子固定时钟跑多条输入轨迹，比帧哈希序列 | **最难骗：要骗必须真的实现一个会按规则响应输入的系统** |
| 像素与音频弱监督 | 帧差与音效事件探测 | 容易骗：背景动画会让每一帧都不同 |

数据解读：最后一条路线的价值在于它**把可玩性转成了一个不需要语义的差分问题**——一条空输入轨迹、一条有输入轨迹、几条不同强度的策略轨迹，剩下的全是序列比较。

还有一个被低估的技巧：对二维画布游戏，**拦截文字绘制调用就能直接从参数里读出分数、生命、关卡，完全不需要光学识别**。这一条把「分数会涨」从半确定性降级成全确定性。它的四个盲区也要一起写：精灵批处理会把逐物体信号抹平（所以「绘制调用数约等于物体数」这个直觉**恰好在网页小游戏最常用的二维引擎上是错的**）；没有语义身份；不被渲染的状态读不到；着色器侧逻辑不透明。

**而动画有一条更便宜的路：不渲视频，直接断言时间轴。** 删掉两整条动画曲线，在单视角、多视角、Chamfer、体素交并比上**全部给 1.0000**，只有逐关键帧断言抓到。要用渲染抓动画，得渲一整段序列，成本至少翻 N 倍。所以在代码生成这个设定里，**时间轴是声明式的，时序正确性应该走断言而不是走视频判别；视频判别的价值在「交互响应」这类无法声明的性质上。**

成本对照也支持这个顺序：一个三轴游戏评测总共约 900 墙钟小时，其中**真玩占 56.8%、重放占 40.1%、源码检查只占 3.1%**。

两句可以直接当结论的处方：**录屏的判官打分只报事件，不定生死；录屏判官的输出进诊断，不进 reward。**

### 6.5 文 + 图 + 视频 + 音频：这一档本地材料未覆盖

把全部素材按音频关键词全量检索，在题的命中只有 6 处，**没有任何一处是测量、公式、噪声地板或 hack 实例**。几个主力素材文件里音频是零命中，一份 2,116 行的一手汇编里没有音频判官、没有音频评分项、没有音频通过判据。

所以这一档只能写三条：

- 音频在抗欺骗排序里是**倒数第二**，只强于「要求模型暴露接口」。
- 技术上有两个钩子可用：拦截音频源的播放时刻，以及读频谱分析节点判断有没有声音在出。它们能验证的是「有内容」「没塌」「输入能改变状态」的弱版本。
- 有一个工程副作用值得单独写：**给页面加声音可以豁免浏览器的后台节流**，于是音频通道顺带解决了「动画帧回调在后台不被调用导致帧计数误判」这个假阳问题。

明确不能写的：音频判据的噪声地板、音频判官的可靠性、音频相关的 hack 实例、把音频纳入分层的权重——**四项全空**。

而这一档真正的价值是一条通用律，它来自一家公开承认的模态盲区：他们的模型**听不见**，所以音乐质检的反馈回路失效。推广开来就是——**判别通道缺失的那个维度，harness 就是瞎的。** 音频对那个模型是这样，三维结构对单张截图是同样的事。

## 7 Verifier As A Layered Gate, Not A Score

参考模态决定了判据来源，而把判据组装成 reward 的方式只有一种形态值得推荐。

核心发现：本项目所有跑通的 verifier 都是合取闸，没有一个是加权求和；而前沿团队公开的唯一一句接近公式的描述也是合取——**任一维度低于硬阈值即整体失败，不做加权求和过线。**

### 7.1 分层的形状：前一层失败就截断

分层规则逐条是这样的：**前一层失败就截断，后层不再计算；核心断言失败时设上限，后面的分再高也不能补回来。** 落到 Web 这条线上：

| 层 | 内容 | 能不能当主指标 |
|---|---|---|
| L0 执行 | 能否无错渲染出帧；在文档内、有尺寸、未隐藏的画布才计数 | 只能当闸 |
| L1 结构 | DOM 盒模型与计算样式回读、图表逐值回读、场景图断言、动画曲线断言 | **能，这是主力** |
| L2 几何 | 逐部件几何、逐颜色体素占据、拓扑量、重叠与出框 | 能 |
| L3 行为 | 输入重放加状态差分；可逆控件测完整循环 | 能 |
| L4 判官 | 判官模型的相对排序 | **只能当小权重的参考项** |

数据解读：层与层之间的判别力差一个数量级。本项目三条线上单条判据的检出都在 10 到 15 个变异（总数约 30），而分层组合接近满分——three.js 侧从 12/29 到 29/29，Web 侧 22/22，图表侧 16/16。更要紧的是留出验证：换一个场景、18 个变异在跑之前就贴好标签、**阈值一个字没动，结果 18/18**。

一条诚实披露要一起写：Web 侧的 22/22 是第二次跑的结果，第一次是 21/22，两个不同原因——一个是真的 verifier 缺陷用错了选择器，一个是变异脚本自己的缺陷。**判别力的提升往往来自消除假阳，不是来自调阈值**；图表侧三个缺陷全是假阳、全是坐标系问题、**全都不是调阈值能修的**。

还有一个反面教材值得留着：类名序列这一层**检出 0/11、误杀 3/11**。**不是所有确定性信号都有判别力。**

### 7.2 两条会反噬的做法

**第一条：把所有断言都打开。** 九族状态断言全查，检出能到 11/11，**但语义等价改写误杀 11/11，保真率 0/7**。误杀集中在两处：把「边长 1 缩放 1.2」改写成「边长 2 缩放 0.6」——世界形状一模一样；以及圆柱分段数 16 改成 32。所以断言必须走**字段白名单，只查题面钉死的那些**。

**第二条：把判官分当主分。** 四个不同家族的判官在同一批变异上的形状高度一致——**保真约 11/11，但 11 个真错误只抓到 3 到 6 个**。多视角拼图几乎没用（16→16、13→14、14→15、14→14），而且**拼图把解析失败率拉高了**。最要紧的一条：**22 个变异里判官抓到的每一个，程序化信号都抓到了——判官独占的检出是 0 个。**

判官的噪声地板也量过：固定温度为 0、每种条件跑两次，**单模型重测翻面率 4.2% 到 20.8%**，最差的一档超过五分之一。四个模型八票多数投票是 44/48 与 46/48，而程序化信号在同一标注集上是 **47/47**。

有一个公式可以把这件事算清：翻面率与单次判对率的关系是 `F = 1 − q^K − (1−q)^K`。一个外部评测实测 7/32 的翻面率，反推单次判对率只有约 12.5%，而**五票多数投票能把翻面率压到约 1.6%**。

判官的误杀还有方向性：它集中在相机。**该过的「相机移动」被八个条件里的四个判错，尽管题面明确写了相机位置变化不算错误**——判官分不清「画面变了」和「场景变了」。

### 7.3 如果非要用判官：相对排序，不是绝对打分

同一个基座上最干净的一组阶梯是这样的：**监督微调 82.5 → 朴素判据 83.0 → 比较器 85.5 → 加循环赛 86.0。** 机制是在同一次调用里给候选和上轮参考打分以共享刻度，两两比，reward 取胜场数，平局 0.5，**渲染失败给 −1**。代价是判官调用次数变成候选数的平方。

一句话：**相对排序优于绝对打分。** 配套还有三条校准要求：判官模型不能是被测模型；有基线时成对比较、随机序、不告知哪个是基线；交换顺序后的一致率不低于 90%。

完整的校准门槛可以直接当及格线：人工裁决 200 对（**通过率落在 10% 到 20% 时要 340 对以上**）、两两一致率不低于 85%、变异测试必做、对抗注入必须判 0 分、取证留三倍、判官与被测模型不同家族。而 verifier 逐条一致率的参照是：专家小组 95% 到 97%，强 verifier 92%，弱 verifier 76% 到 82%——**要求不低于 92%，绝不低于 85%。**

### 7.4 审美维度：只能当双侧区间，而且天花板在 60%

这一节的结论在第 3 节已经出现过一次，这里补齐它在 reward 侧的形态。

核心发现：单一全局审美 reward 的天花板约 60%，因为人自己就不一致。

20 位职业设计师评同样 600 对，二元一致率只有 **0.624**、一致性系数 0.248，**28.5% 的对子分歧率不低于 96%**；在这份数据上训的模型汇总只到 57.45%，个性化到 60.16%。

而换成整体美学分会立刻被刷穿：美学分从 4.309 涨到 6.697，**而评分项分从 0.395 掉到 0.262，低于零样本基线，输出长度翻了 21 倍**——堆叠重叠描边与重复装饰。换成结构化评分项之后，hack 换了形态，变成「把需求词画成风格化标签」。

所以审美在 reward 里的正确位置是：**双侧区间或否决闸，不是单调排序器。** 而「AI 味」更不能做单样本 reward，因为它是分布量——发散任务的变异度在模型侧是 0.459、人类侧 0.738，而个体原创性 0.711 对 0.696 没有差别。它只能当批次诊断。

统计上还有两条省钱的结论：**加题比加人划算**——评分人数从 3 人加到 16 人，人力是 5.3 倍，题量只省 30%；而**十个判官只值 3.5 个**，因为判官之间的错误相关系数是 0.206，换训练种子买不到独立性，加第二个种子只让有效样本数涨 0.11。审美维度上 30 题乘 8 次采样的最小可检出差异约 **15.4 个百分点**，想读到 5 个点需要两千多次采样——不划算。

### 7.5 判别力怎么量，以及什么时候该停

四个指标就够：检出率、误杀率、保真率、以及两者之和减一。配套用威尔逊区间，零事件时上界取三除以样本数。

在线监控有四个量，而其中一条警告最要紧：**正的平均增益不是没有 hack 的证据**——同一批里有 26.4% 的样本比基线更差。可用的停训信号是自内化差距，它的峰值出现在判官小组共识峰值的 100 步以内，**而训练用 verifier 自己的 reward 在最后一个检查点之前从不见顶**。起病窗口在 68 到 478 步之间，**而从起病到灾难只有约 100 步**。还有一条检出能力的分界：句法型 hack 在匹配率 0.6 到 0.95 区间可检出，**语义型只有 0.0 到 0.4**。

最后两条方法论，它们比任何单个阈值都重要：

- **「能把该挂的和不该挂的分开」不等于「能当闸」。** 还要看余量、好样本在哪一侧、极端情形会不会翻向。最佳实例是栅格对齐：参考页 0.824、该挂的两个 0.707 与 0.794、**而该过且审美更好的那个却是 0.765，比该挂的更接近失败**；更糟的是**抹掉所有边距的那个对齐率反而是 1.000**。存在可分离阈值，但余量只有 0.058，方向在极端情形下翻转——**作废当闸，只留作连续诊断量。**
- **信号在它自己验证的那个样例上造出来的，就不算独立验证。** 那个开放边界边数信号是在某个样例上创造的，所以「加了之后 13/13」不是独立验证。同理，变异集不能既当调参集又当验收集——某个颜色容差是在同一批 13 个变异上调出来的，所以 13/13 是过拟合。

## 8 Harness: Many Assets, No Repository

SWE 类任务的 harness 形态是「一个实例一个镜像」：把整个代码仓库连依赖一起冻进镜像，模型进去改代码，跑测试。视觉生成类任务不是这个形态。它的沙箱里**参考素材很多，代码仓库几乎没有**，因此上下文也短一个数量级。这一节把这个差别量化，因为它直接决定 rollout 的单价。

### 8.1 The Asset-Heavy， Repo-Free Shape

核心发现：视觉生成任务的镜像是按依赖集共用的，而 SWE 的镜像是按实例独占的。

| 维度 | SWE 类 | 视觉生成类 |
|---|---|---|
| 素材供给 | 爬 PR，一条任务一段 diff | 成对且单文件：本项目的 three.js 素材线是 610 个页面对 610 张截图，一比一 |
| 单条体积 | 仓库级 | 每条样例中位数 6,137 字节 |
| 镜像组织 | 一实例一镜像 | 一个依赖集一个镜像，一个镜像挂几百道题 |
| 环境侧总量 | 公开合成集每实例约 6 MB，乘 50,137 条 | Web 层固定约 0.6 GB，不随题数增长 |
| 启动 | 容器起+依赖装 | 浏览器起 172 到 191 毫秒，场景载入 401 到 420 毫秒，复用页面只要 50 毫秒 |

API 面也不大：three.js 侧统计到的可用接口是 1,251 个，这是一个模型可以在上下文里带着走的量级，而不是一个需要先检索再用的量级。

最硬的一组对照在上下文上：

| | 本项目视觉编码轨迹 | 公开 SWE agent 轨迹 |
|---|---|---|
| 累计输入 token | 约 1.06 M | 5.55 M |
| 输出 token | 约 32 k | 32.5 k |
| 步数 | 40 | 111.2 |

数据解读：输出几乎一样，输入差 5 倍，步数差 2.8 倍——**累计输入基本等于步数的平方量级**，因为每一步都要重带前面所有观测。所以控制视觉任务 rollout 成本的第一个旋钮不是分辨率，是步数。顺带推翻一个直觉：**图像只占累计输入的 8%**，三张常驻的多视角拼图是 2,109 token，40 步累计图像约 84 k。把图砍小换不来多少钱。

### 8.2 Determinism Is A Ladder With A Hard Top

判据要能复现，前提是产物能复现。本项目在无头浏览器上做过完整阶梯实测：不控制则三次全不同；只装虚拟时钟仍然三次全不同，因为页面加载本身耗时 113 到 432 毫秒会漏进时间源；加上暂停、定长推进与种子化随机之后，20 次里只剩 2 种；**只有当页面主动暴露时间钩子、并且直接读画布像素时，三次才逐字节一致**。

综合基线是这样的：把全部可观测字段铺开数 231 个，在固定视口、固定设备像素比、关掉字体 hinting、镜像内打包固定字体并禁止联网拉字体之后，**只剩 4 个字段会变**。

但这道阶梯有硬顶，四条必须写进文档：

- **工作线程里的时钟拦不住。** 因此有一批用到它的样例只能整批排除，本项目的对应口径是 225 条。
- **断网会造成假阳性。** 封掉外链确实能稳住渲染，但同时也会封掉用来注入判据的那一路，结果是「判据没跑」被读成「判据通过」。
- **跨引擎版本的逐字节一致从没被测过**，而且有反向证据：超越函数在不同引擎版本间会发散，某物理库在两个相隔较远的引擎版本之间结果不同。所以版本要钉死，不要假设能跨。
- **种子不是万能的。** 固定种子能把一个布局噪声从 0.00167 压下去，但它仍然小于该任务自身的判据容差 0.0046——也就是说，这道闸带来的收益在该量程上读不出来。

### 8.3 Visual Verification Does Not Need A GPU Sandbox

核心发现：视觉验证的单价是毫秒到秒级，而且不需要 GPU。

| 配置 | 吞吐 | p50 |
|---|---|---|
| 1 浏览器 1 页 | 2.4 任务/秒 | 383 毫秒 |
| 4 浏览器 8 页 | 11.6 任务/秒 | — |
| 8 浏览器 8 页 | 14.3 任务/秒 | 4.1 秒 |

同一批实测里，**组织方式比机器重要**：单进程逐题起浏览器是 3.6 任务/秒，复用浏览器后到 14.3，差 4 倍。单条任务耗时横比是 three.js 383 毫秒、Blender 2.3 秒、Web 页面 4.9 秒、图表 840 毫秒；折成单位成本是 3.35、24.7、56.3 核秒。换成一轮 1024 条的 rollout，多轮 three.js 任务要 43 核，单轮 Blender 任务要 1670 核——**差 39 倍，而这个差距来自技术栈，不来自算法**。

公开世界里唯一一份「渲染型判据在 RL 里占多少时间」的数字是 75.4% 生成、22.4% 渲染、2.2% 比对。渲染不是瓶颈，生成才是。

GPU 这件事可以直接定论：三类技术线都能在无 GPU、无显示的机器上跑完整渲染，浏览器走软件光栅后端，Blender 的多个版本都能跑三种渲染引擎。而公开沙箱平台里，**没有一家写明支持「GPU 加图形栈」**——想要真 GPU 光栅得自己做镜像，CPU 方案能省掉这一整套。一个踩过的坑：新版浏览器不显式开启就建不出 WebGL，而**顺手关掉 GPU 的那个开关会把软件渲染后端一起关掉**。

### 8.4 Give The Agent Structured Observations， Not Screenshots

核心发现：自检工具里最便宜、信号最强的几样都不是图。

| 工具 | 成本 |
|---|---|
| 读场景图 | three.js 1.8 毫秒，Blender 0.1 到 1 毫秒 |
| 读控制台 | 近乎免费，抓到一条资源 404 就证明观测通道是通的 |
| 逐值回读图表数据 | 1 到 4 毫秒，是渲染耗时的千分之四 |
| 单张截图 | 64 到 85 毫秒 |
| 读无障碍树 | 注入 72 毫秒，首次运行 71 毫秒，之后 30 到 34 毫秒 |
| 真实键盘遍历 | 40 次焦点切换 36 到 40 毫秒 |
| 八视角：逐张截图 | 477 到 540 毫秒 |
| 八视角：一次求值内渲完再导出 | 192 到 202 毫秒 |
| 真实交互状态机 | 7 条断言加 8 次重载 2,267 毫秒，单项最贵，占整个探针的 46% |

数据解读：返回结构化 JSON 的成本是毫秒级，看图要花 token。渲染型任务比纯界面操作类任务多一张牌——**运行时状态是精确、无损且便宜的**，没有理由让模型靠看图去猜一个能直接读出来的数。

图像预算则要在环境层硬性规定。按主流计价公式，一张 1024×768 是 1,036 token，八张逐张发是 8,288；降到 512×384 是 266 和 2,128；**而把八视角拼成一张 1024×512 的联络图只要 703 token**。所以默认给拼图，要细节再按需放大。进一步的工程结论是：**每条轨迹的视觉 token 上限要写进环境，超了就强制降分辨率——这是 RL 成本的主要旋钮。** 还有一条会直接报错的边界：超出分辨率上限的图片不会被自动缩放，而是直接报错。

## 9 Picking What To Distill

这一章的最后一个问题是选题：像截图转代码这种大部分是简单题的方向，怎么挑出值得花教师算力的那些。直觉做法是算 reward、取低的、让教师跑一遍、再决定要不要蒸。这个直觉的方向是对的，但它在素材里成立的形式需要改一个字。

核心发现：素材里的正面证据全是间接的，反面证据全是直接实测的。所以成立的命题不是「reward 越低越值得蒸」，而是**「reward 低先做归因分型，分型之后才知道该不该叫教师」**。

### 9.1 First Fix The Difficulty Band

在谈选哪道题之前，先得有一个通过率估计。各家的预算差别很大，但口径高度一致。

| 工作 | 用谁采 | 采几次 | 保留区间 |
|---|---|---|---|
| 某推理模型 | 强推理模型 | 10 次 | 0 < p < 0.9 |
| 某对话模型 | 待训模型 | 3 到 12 次，取平均解决率 | 两端都砍 |
| 某开源大模型第二阶段 | 待训模型 | 8 次全败且 512 次内可解 | 只要极难但可解 |
| 某边界感知课程 | 待训模型 | 256 次解码 × 3 个种子 | 分五档，包括全败档 |
| 某网页任务管线 | — | 4 次 | 0 < p < 0.5 |
| 反例：某系列模型 | 完全不做通过率课程 | — | 只过滤难验证的题，最后只剩 3,995 对题与判据 |

三条可以直接用的口径：

- **上界不是 1，是 0.9 甚至 0.5。** 通过率太高的题在分组相对优势算法里和全败题一样没有梯度，但代价不同：全对题浪费 rollout，全败题还会污染组基线。
- **难度带筛选本身的价值有一个干净的对照值：不做 54.2%，做了 57.8%，差 3.6 分。** 这是目前唯一一组「做 vs 不做」的同条件对比，可以当上限参考。
- **零梯度组的占比比想象的高。** 任务初期通过率 5% 到 10% 时，组大小 8 的全败组占 43% 到 66%。而「全败」往往只是采样预算不够：同一个模型同一批题，单次通过率 26.5%，256 次通过率 81.3%——**信号坍缩是欠采样的统计假象，不是模型上限**。

还有两条结构性的事实。一是**静态课程失效得极快**：第一轮 RL 就把易档从 24 道冲到 650 道，之后几乎不动（650 到 697 到 736）。所以重估通过率的边际价值绝大部分在第一遍。二是**组大小是二阶的，批大小才是一阶的**：固定总批量下组大小 8/16/24/32 得到 0.585/0.610/0.590/0.595，非单调且在噪声量级；而批大小 512/768/2048 是 0.605/0.610/0.645，单调上升。先把批做大，组取 8 到 16 够了。

本项目有一条自己的预算约束必须讲清：Blender 线单视角单题 24.7 核秒，照 256 次乘 3 个种子算是每题 5.3 核时，三千道题就是一万六千核时，**和跑一轮 RL 同量级**。所以离线跑高预算通过率估计这条路在本机不可行，只能用训练中的在线正确率。

### 9.2 Five Reasons A Reward Is Low

这是本章最该被当成检查表的一张。每一类的处理方式都不一样，而其中只有最后一类该叫教师。

| 类型 | 怎么认出来 | 公开或实测证据 | 处理 |
|---|---|---|---|
| 题目坏了 | 多个强模型互相不一致，或普遍与标准答案不一致 | 自动出题的题坏率：50% 小问题、7% 大问题；某执行环境里能区分对错补丁的测试不到 20% | 退池，别叫教师 |
| 判据坏了 | 负例里出现三个以上判官一致判挂 | 单判据的天花板低于能力上限约 20 个百分点；本机有一条金标签标错，剔掉它之后多视角特异度从 0.891 回到 1.000 | 先复核标签 |
| 重跑抖动 | 同样的轨迹重跑会翻面 | 54 条原本成功的执行各重跑三次，162 次里 85 次失败，54 条里 39 条至少退化一次——**而温度是 0**；纯回滚重采样自己就能救回 16% | 先减掉这条基线 |
| 判据被豁免或判对了理由错 | 判定对但诊断错 | 本机单条件判定里 50%、多条件里 67% 明确援引取景或透视豁免放过了真错误；某个「鼻子长在后脑勺」的样例八次全判挂，但 0/8 的理由提到了朝向 | 按诊断正确性打标 |
| 预算耗尽或环境故障 | 看终止原因 | RL 早期约 20% 的轨迹被轮数或 token 耗尽截断，而离线复核发现其中 24.3% 其实已经解决了问题 | 分开处理，见下 |

最后一类的处理方式有一组罕见的正反对照，值得单列。公开做法是把预算耗尽判为「强制提交并把 reward 乘 0.5」，把环境故障判为「屏蔽梯度」，只有模型自己的错才正常回传。**而把预算耗尽也按环境故障处理（给 0 分并屏蔽）的那一家，在复现这套时 reward 持续下降直到训练崩溃。** 部分分在这里不是精细化，是必需品——没有它，真实进展会被归零。

但「部分分越细越好」立刻就有反证：某评分细则从第一版细化到第四版时择优准确率从 57.9% 涨到 67.4%，**而过度细化的第五版全面变差**。更狠的一条是：在某数学模型上，随机 reward 带来 +21.4，格式 reward +13.8，错标签 +24.1，**而真标签 reward 也只有 +29.1**——**没有空白基线的代理增益不说明任何事。**

### 9.3 Spotting Bad Tasks Without Human Annotation

上一节第一类是最大的那一类，所以要专门说怎么判。先把人工标注这条路否掉：同一份评分细则下，「题面欠规约」判定的标注者一致性只有 0.24，测试充分性 0.41；一次独立复刻投入 7 名研究者、7 周、约 882 人时，一致性始终落在 0.0 到 0.4，从未过可信阈值。**而同一批人标「难度」时一致性是 0.78。** 也就是说，人能一致地判「难」，不能一致地判「坏」。

而「难」与「坏」确实可以被量化分离，最干净的证据是：同一批模型、同一条流水线，**「模型错误里有多少其实是数据集的错」这一列从 0% 一直横跨到 93%**——两个数据集是 0%，而几个算术类数据集在 89% 到 93%。做法本身也是最低成本的坏题筛法：把每题发给多个前沿模型，只人工复核至少有一个模型答错的题；标准答案错会表现为前沿模型普遍与它不一致，题本身坏会表现为模型互相不一致。

推荐的主路线是响应模式统计，而不是标注。两个量就够：

- **区分度。** 在双参数项目反应模型里，难度高是正常的、是我们要的；而**区分度小于等于零说明题坏了**——能力越低反而越容易答对。零方差的题（所有模型全对或全错）区分度不可识别，公开统计里占全量约 4%。
- **题总分相关（必须用剔除自身的版本）。** 理论上若模型成立，这个相关必为正，所以低或负就是单维假设被违反。经典阈值是 0.30 以上良好、0.20 到 0.29 勉强、低于 0.20 需修订、小于等于 0 红旗。实测效果：约一千题的集子一分钟跑完，每个集子只把 50 题送专家，**被标出的题最高 84% 经人工确认有实质缺陷**，并且在一个已被人工修订过的集子上又找出 16 条此前没发现的无效题。

一个必须一起说的注意事项：区分度在极易和极难题上会被天然压低，**不能脱离难度孤立判读**。

判「题面欠规约」则有一个程序化做法：**给题面补上参考信息再重测通过率，跳升超过 0.3 就判欠规约。** 公开世界的同类证据是，给检索增强换成直接给出相关文件位置，解决率从 2.27% 跳到 4.01%、从 0.70% 跳到 4.54%——之前的失败很大一部分是信息没给到，不是不会做。另一侧的 ceiling 是人类上限：某代码基准给最终题面随机分配标注者，人类解出 32/33，低于这个阈值的题就是测试过严或题面欠规约。

### 9.4 When To Actually Call The Teacher

归完型之后，叫教师的判据只有一条，而且它不是「reward 低」。

**是「教师解得出，而学生解不出」。** 某模型的难度过滤就是这个动作：保留那些待训模型极少答对或一贯答错、**但更强的教师仍可解**的题。低 reward 本身不是丢弃标准，「教师也解不出」才是。

而当确实存在明显更强的教师时，蒸馏对 RL 的优势是数量级的：RL 花 17,920 GPU 小时得到 67.6，**同策略蒸馏花 1,800 小时得到 74.4**——十分之一算力、全面更好，而且原文还补了一句「RL 完全没有提升高预算通过率」。由此可以直接写出三分法：

1. **有明显更强的教师，就蒸馏，别 RL。**
2. **没有更强教师、或教师也失败的方向，RL 是唯一选项。**
3. **想扩高预算通过率，RL 必须带课程**——否则会反向：某模型在一个数学集上 40.0 到 26.7 再到 52.2，无课程的 RL 把能力边界**缩小**了。

落到本文三个技术栈上，优先级是清楚的：**前端与网页开发先蒸馏；three.js 与 Blender 的复刻类任务 RL 信号最干净，先做；开放式 3D 设计（教师和判据都弱）放最后。**

全败档也不是丢掉。可抄的做法是取最靠近两个预算边界的各十道题，**做小规模教师轨迹桥接再 RL**，实测高预算通过率比基线高 9.8 个百分点、比无课程 RL 高 10.3 个百分点，**538 道原本解不出的题里有 226 道变得可解**。

成本侧有一条最硬的反对意见要摆在一起：**rollout 占 RL 运行时间的八成以上**，所以「多采一倍候选再挑最好」这类做法很贵。这也是为什么前面那套分型必须先跑完——它的全部意义就是把教师 rollout 的开销压到真正需要的那一小部分题上。

### 9.5 What To Distill， Not Just Which Task

最后一个常见错误是：选对了题，却蒸错了轨迹。

核心发现：把试错过程删干净的「纯净轨迹」，会换来同分布上的小涨和跨环境上的大跌。

一组四变体消融说得最清楚：完整版（错误轮被屏蔽梯度）在训练同域上 48.5，**纯净版 49.3**——略高；但换到两个未见环境，**从 21.7 掉到 11.7、从 5.0 掉到 0.0**。另一组更直接：只用最优轨迹训出 10.84，带修订的训出 46.75，而只在末尾纠错是 35.67——**早截断优于末尾纠错**，而且把「本来就对、没有修订」的轨迹混进去会降分。

负例的正确处理方式是加权，不是删：一次权重扫描给出 0.0 对应 37.2%、0.5 对应 35.1%、1.0 基线 41.8%、**0.8 对应 44.4%**——0.8 是唯一超过基线的一档，而且这条曲线非单调（0.5 比 0.0 更差），原文没有解释。**别删负例，也别把权重归零。** 顺带要承认一个空白：纯净与带纠错的配比**没有任何工作做过系统扫描**，公开的几个点各自是任意的，从七三起当超参是推断，不是结论。

还有两条关于「错误从哪来」的硬结论：

- **离线修正轨迹学不出自我纠错。** 一次干净的对照里，离线配对微调的两轮改善率、错到对率、对到错率**全是 0%**——离线纠错微调的自然收敛点就是「第二轮一字不改」。失败机制有两个：学会纠的是基线模型的错而不是自己的错，以及行为坍缩成「第一轮答好、第二轮别动」。
- **错误必须来自策略自己。** 可抄的做法是让待训模型先失败，在失败处快照整个虚拟机，**让教师从这个失败状态继续**（只告诉它上次失败了，不给隐藏判据细节）。这样做出来的数据在训练用的 harness 上比同规模基线高 14.6 个百分点，**换到三个完全不同的 harness 上仍然高 6.7 到 12.4 个百分点**。原文点名的原因是：手工注入的错误与 agent 自己执行时产生的错误分布不匹配。一个工程细节值得一起抄：快照要在尝试结束时做、之后再恢复跑判据，免得判据自己的改动污染快照。

所以把整条选题链路串起来，它是这样的：**先定难度带 → 低 reward 先归因分型 → 退掉坏题与坏判据 → 减掉抖动基线 → 剩下的题里挑「教师解得出而学生解不出」的 → 让教师从学生自己的失败状态往下接 → 蒸带试错的轨迹，负例降权不删。** 本章开头那个直觉「reward 越低的，再由教师跑一遍，判断是否蒸」在这条链路里仍然成立，只是它不是第一步，而是第五步。
